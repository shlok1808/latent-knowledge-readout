## Code read (2026-11-04, github.com/orgadhadas/harm_pruning, read-only, nothing run)
- Gradients are scored ONE LAYER AT A TIME: per layer, grads are enabled only for that layer's 7 projections, then every example is passed forward and backward (prune_utils.py:330-358). Memory stays small; README: Llama-3.1-8B pruning takes about 20 min on one L40 (48 GB).
- Score: |w| or w times the summed grad (prune_utils.py:176-191). Signed for pruning (`--no_abs --neg_prune`, so -w*dL/dw); preservation `--abs_preserve` = |w| * sum_i |g_i|, i.e. per-example abs (batch of 1). Matches 2610.28325 Eq. 1-3.
- Loss: HF causal-LM mean CE over the response tokens only; prompt tokens are -100 (data_utils.py:93-95).
- Target y for pruning data: the model's OWN generation (generate_model_answers.py writes clean_prompt/clean_response).
- Pruning-data text: decoded chat-templated prompt + "\n" + response, add_special_tokens=False. For Llama, the prompt is templated with add_generation_prompt=False, so no assistant header precedes the response (generate_model_answers.py:171-176, data_utils.py:73-79). This is a quirk; unknown whether the sycophancy paper kept it.
- Preservation Alpaca: "alpaca_cleaned_no_safety_train_raw", raw text with no chat template, response prefixed by "\n" (data_utils.py:49-71). Data CSVs are on Google Drive.
- Eligible: the 7 projections for Llama-3.1-8B (Instruct and base) (prune_utils.py:25); README `--p 5e-05`; sampling `shuffle(seed).select(n)`, seed 0.
- Selection: per matrix top-q minus top-p (prune_utils.py:465-488). OLDER than 2610.28325's percentile rank + global top n. No random magnitude-matched control in the repo.
- Training stages (§3.3, Fig. 4c, App. G): B-TAP across the OLMo-3-7B checkpoint sequence (base -> mid-train -> long-context -> SFT -> DPO -> RL) for HARM; separability "emerges gradually with alignment training, especially after preference optimization". Method: utility-vs-harm trade-off curves over sparsity levels. Caveat in the paper: alignment vs more training is hard to separate without a controlled run. Relevance: a template and a prior for our Step 2 (prune per stage); ours differs in behaviour (sycophancy + useful updating, shared weights). OLMo-3 has a fuller open stage sequence than Tulu.


## Full-text findings (2026-11-05, agent read; verify quotes before citing)
- Score I = W·∇W L averaged over the pruning set, signed (negative = facilitates). Preservation = unsigned SNIP (App A.1: "sign is more sensitive to noise"). Selection = top-q pruning minus top-p preservation; Llama-8B p = 7e-4, q = 4e-5 (App M), tuned per model on validation data.
- Data: 412 AdvBench prompts for pruning + 100 validation; target = the model's own jailbroken reply (base models: first 10 tokens prefilled from instruct). Preservation 412 Alpaca (>128 helped; more did not).
- Format: paper says scoring uses the raw format, not the chat template (template made scores pick template-processing weights). The code templates the user turn but omits the assistant header (data_utils.py:74-78), so "raw" likely means "no assistant header".
- Controls: magnitude-matched random (per module, 20 |W| bins, 3 draws) "close to a no-op"; next-ranked control (App E.2); factual knowledge NOT separable (App D). No test of whether the selected set is stable across seeds or data subsets.
- Stages (OLMo-3, Table 13): separability emerges mostly at DPO; caveat: cannot separate alignment from more training; p/q re-tuned per model confounds cross-stage comparison.
- Admitted: necessity, not sufficiency; spillover (over-refusal on benign financial advice).
