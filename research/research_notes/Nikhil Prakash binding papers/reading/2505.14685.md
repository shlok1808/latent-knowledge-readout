Read: main text in full, appendices skimmed (D behavioral table, F causal abstraction, H DCM masks, K knockouts, M BigToM, N 3-triple). Figure pages viewed: p03. Read 2026-10-26, about 8 minutes.

## Simple
- Task: CausalToM, short template stories. Two characters each fill one opaque container ("Bob fills a bottle with beer, Carla fills a cup with coffee"). Question: "What does Bob believe the cup contains?" Answer is a state or "unknown". There is a variant with visibility sentences ("Bob can observe Carla's actions").
- Models: Llama-3-70B-Instruct (main), Qwen2.5-14B-Instruct and Llama-3.1-405B-Instruct (Appendix N, same mechanism). They were chosen because they score over 80% in both conditions (Table 1, 10 runs x 100 samples). Most smaller models fail the task.
- Method: they write a hypothesized causal model, then test each variable with interchange interventions (patch a residual or a DCM-learned low-rank subspace from a counterfactual run). Metric: IIA. n = 80 correct samples per experiment. DCM masks are trained on 80 and validated on another 80.
- Finding, the "lookback": a reference (an ordering ID, "first or second") is copied to two places. The address copy sits next to a payload. The pointer copy sits at a later token. Later, attention matches pointer to address (QK) and pulls the payload (OV). It works like a pointer dereference.
- Three lookbacks: (1) binding: character and object OIs are bound to the state OI at the state token, then the question's pointers fetch the state OI; (2) answer: the state OI fetches the actual state word; (3) visibility: a visibility ID lets the observing character pull in the observed character's info.
- Layers in Llama-3-70B (80 layers): source OIs at layers 20-34; binding at the state token 33-38; answer pointer at the final token 34-52; answer payload fetched 52-56; visibility source 10-23, lookback 24-31.

## What it means for us
1. **Counterfactual pair design (Stage A, every fate).** Their pairs swap one variable while every other token stays aligned. They copy states "between identical tokens". Our pushback twin (with and without "I'm sure it's Sydney") changes the token count, so positions do not line up. Fix: template the pushback so both versions have the same length (for example "I'm sure it's Sydney" vs "I'm sure it's Canberra", or a neutral filler of the same length). Patch at matched positions only.
2. **Causal-abstraction recipe (Stage A; H3).** Write the high-level model first (for example: retrieve fact F, read the user claim U, compare, select output). Give every variable a counterfactual that predicts a different output. Their DCM subspace is learned by maximizing the causal-model logit, which can overfit, so they hold out 80. Our DAS/DCM step should do the same. Appendix M: the same variable sits in *different subspaces* on BigToM vs CausalToM. That supports H3 (probes fit on one distribution can miss the variable on another) and argues for refit-vs-frozen probe comparisons. It also warns that a "transformed" verdict could be just a distribution-shift subspace change.
3. **Earliest-patch failure diagnosis (user takeaway (a): partly holds).** True: they study only correct samples. Failures are not analyzed. But the "pair wrong with matched correct, patch variables in order, the earliest fix marks the break" recipe is *not in this paper*. It is our extension. Two traps they show us: (i) a full-residual patch at an early layer copies everything and "fixes" trivially. So patch variable-specific subspaces, and freeze the downstream site as in Fig. 6 (freezing the state token was needed for alignment, Fig. 13). (ii) Fig. 8: patching only the address or only the pointer gives near-zero effect at layers 24-31, but patching both works. So "the patch did nothing" can be a pointer/address mismatch, not inert info. That would make us mislabel override or not-routed as **bypass**. Stage A should include a joint address+pointer patch before calling bypass.
4. **Pointer vs value (user takeaway (b): partly holds).** The lookback needs both candidates *in context* as tokens with addresses. In single-turn pushback, "Sydney" is in context but "Canberra" may be only parametric. Then there is no second address to point at, and the selection is not a lookback. It fits best when the model's own earlier "Canberra" answer is in the transcript (multi-turn pushback, H1 pressure condition 2). Then the strong test is the Fig. 4 pointer patch. Patch the "which-candidate" pointer from a run that picks the other candidate. A pointer swap moves the answer to the *position* the pointer names, and a value swap moves the *content*. Pointer-vs-value separates **override** (the selection signal points at the user's slot) from **transformed/not routed** (the value at the slot is wrong or missing). Condition 1 (one competing answer, both in the prompt) is the cleanest place to test it.
5. **Where in the architecture (Stage B).** In the 70B model, selection (pointer, mid layers) is separate from fetching (payload, late layers 52-56) and done by different heads (Appendix L head-norm alignment). If pushback breaks at the pointer, a fix aimed at mid-layer QK selection is fate-matched. If the break is at the fetch, a late OV/payload fix is the matched one. That is a concrete H2 contrast with plain DPO.

## Caveats
- Synthetic template stories with 2 characters and 2 objects (3 in App. N). The answer is copied from context, not recalled from weights. Our fact (Canberra) is parametric, so these mechanisms transfer only to the in-context parts of pushback.
- Only correctly answered samples, so it says nothing about how failures happen. All evidence is interchange interventions, which is causal controllability. High IIA on natural correct runs supports that the model uses this path normally, but they never test endogenous mediation on errors. Visibility payload semantics are "initial evidence" only.
- Models: 14B, 70B, 405B, picked because they succeed. Smaller models (7-8B) mostly fail the task, so the mechanism may not exist where models fail. That is relevant to our 9B-27B range. Gemma-3-27B is in Table 1 but is not analyzed mechanistically.
