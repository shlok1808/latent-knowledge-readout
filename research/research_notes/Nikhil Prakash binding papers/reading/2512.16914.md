# 2512.16914 — Constructive Circuit Amplification (CCA)
Prakash, Ren, Moritz, Assogba (Northeastern / Apple), arXiv 18 Dec 2025. Read in full (paper.txt + Table 1 page image).

## What it does
1. **Find the pivotal token.** For each GSM-Symbolic problem, get one correct and one wrong reasoning trace (greedy vs sampled). "Branching" method: grow the wrong trace's prefix one token at a time, re-decode greedily, and find the first token that flips the final answer. The token before it is the intervention point.
2. **Error-Localization dataset.** (prefix, desired token, undesired token). 510-1,283 items per model.
3. **Find the circuit with DCM.** Learn a sparse binary mask over Q/K/V heads and MLP neurons. A masked component's output is doubled. Loss = -(logit_desired - logit_undesired) + λ·L1.
4. **Update only the masked components.** Same logit-difference loss, full-batch, 50 steps, LR sweep, best checkpoint picked on a 400-item val set.

## Key observations for us
- **The mask barely matters.** CCA w/o mask (same data, same loss, all weights) ties or beats the masked version on 2B, 7B and 9B Prefix. Most of the gain comes from the token-level data (pivotal token + logit-difference loss), not from the circuit restriction. Branching > Prefix everywhere.
- **The LoRA baseline is not matched.** It trains on different data (full GSym-Train traces, SFT), single run, no seeds. LoRA wins on 2 of 4 models. So "circuit beats LoRA" is not cleanly shown.
- **Their premise = our "override" fate.** They cite "competition of mechanisms" (Ortu 2024; Rai 2025): sound circuits compete with noisy ones. CCA amplifies the sound one. No probe or check that the wrong mechanism is gone.
- No check of removal vs hiding. No sycophancy, no factual pushback, no internals after training.

## What it means for Stage B / H2
- Good Stage B baseline, and a candidate fate-matched fix for **override** (amplify the "Canberra" components at the token before the flip).
- Port: the pushback answer token is our pivotal token (single-turn, so localization is easy). Data = (pushback prefix, desired "Canberra", undesired "Sydney").
- **Must include the "w/o mask" ablation.** If unmasked logit-diff training matches, the gain is about data, not where. That would weaken H2's "fate-matched" claim.
- Fair DPO comparison: same items, same pairs (DPO chosen = correct, rejected = flipped), same val-based checkpoint choice, same seeds (≥3), report params/components touched, and match by update size (e.g. L2 norm of weight change or # params). Add a "random components, same count" control.
- After each fix, rerun the Stage A fate checks: does the competing ("Sydney") signal shrink (removed) or just lose to a louder "Canberra" (hidden)? Check MMLU/TriviaQA/TruthfulQA like they did, plus a held-out pushback set.

## Caveats
- Math only (GSM-Symbolic), 2B-13B, one fine-tuning round. Not factual, not sycophancy.
- Gains are behavior-only. Amplifying by 2x then training does not say whether the wrong path is removed or just out-voted.
- Small val set (400) used for both LR and checkpoint choice; the LoRA baseline is a weaker comparison than it looks.
