## What Is Variable Binding and Why It Matters

* Variable binding: associating a representation with the correct entity, not just generating representations of individual objects
   * Example: seeing a cat in a red cap and a horse in a fedora, the brain binds "red cap" to "cat" and "fedora" to "horse"
   * Swapping the hats in the image does not break comprehension because the binding, not just the percept, is stored
* Historical stakes: the 1980s debate between Symbolic AI and connectionism
   * The central argument against connectionism was that deep neural networks cannot perform variable binding correctly
   * Connectionism has since won empirically, but the mechanistic question of how neural networks do binding remains open
* Contemporary relevance: variable binding underlies code execution, arithmetic, theory of mind, and multi-step reasoning
   * Nikhil's thesis argument: to properly understand any of these complex behaviors, we must first understand the binding mechanism inside the model
* David Bau's framing in his introduction: Nikhil joined wanting to work at the boundary between AI and human cognition, specifically on AI theory of mind, which was controversial (Gary Marcus argued neural networks could never do it, partly based on 1980s theoretical work)
   * Early open models could not do theory of mind; commercial models appeared to be able to
   * Nikhil's work studies models of increasing size and capability across his PhD

## Paper 1: Fine-Tuning Enhances Existing Mechanisms (ICLR 2024)

* Task: entity tracking, a purely text-based task
   * Prompt structure: a sequence of sentences, each placing one object into one labeled box (e.g., "Box A contains an apple, Box B contains a kite…")
   * Final sentence: "Box C contains…" and the model must predict the correct object
* Model studied: LLaMA 7B, base model and several fine-tuned variants
* Step 1: circuit discovery using path patching (an algorithm from prior mechanistic interpretability work)
   * A circuit is a minimal subset of model components sufficient to perform a task
   * Four groups of attention heads (A, B, C, D) were identified; ablating all other components leaves task performance fully intact
   * Group relationships:
      * A and B are connected via Q-composition: output of group B forms the query vectors of group A
      * B and C are connected via V-composition: output of group C forms the value vectors of group B
* Step 2: understanding what each group does via interchange intervention (activation patching)
   * Method: create a counterfactual prompt that differs from the original in a specific, controlled way; run both through the model; patch activations from the counterfactual run into the original run at specific components; observe how the final output changes
   * Group A heads: patching from counterfactual changes the output from "apple" to "kite"
      * Group A primarily attends to the correct answer token and fetches its value
   * Group B heads: patching from counterfactual changes the output to "map" (not the value of the labeled box)
      * Surprising finding: the model is not copying the object token directly
      * Group B tracks the positional index of the correct answer token; group A then uses that index to fetch the value
      * The model uses position-based tracking, not direct value retrieval
* Key result: the same circuit, with the same functional roles for each head group, is found in fine-tuned versions of LLaMA 7B
   * Fine-tuning on structured tasks (code, arithmetic) does not create a new mechanism; it enhances the existing one
   * Takeaway: fine-tuning is more like amplification than reprogramming

## Paper 2: Language Models Use Lookbacks to Track Beliefs (ICLR 2026)

* Task: theory-of-mind belief tracking
   * Two characters, Bob and Carla, work in a restaurant
   * Bob fills an opaque bottle with beer; Carla fills an opaque cup with coffee
   * Question: "What does Bob believe the cup contains?" Answer: "unknown" (Bob did not observe Carla's action)
   * Purely text-based; images in slides are illustrative only
* Model: LLaMA 70B, which can perform this task well
* Mechanism (basic setting, no explicit visibility):
   * Step 1: model generates ordering IDs in early layers (e.g., "I am the first character," "I am the second container," "I am the first drink")
   * Step 2: IDs are moved to the drink token position
      * The drink token is the last of the three key entities (character, container, drink) in a causally attended transformer; it is the only one that can attend to all three
   * Step 3: IDs are also passed to the queried character and container tokens in the question
   * Step 4: at the final token, attention heads look up which drink token carries the matching IDs (e.g., green-two and yellow-two), then fetch that drink token's ordering ID, then fetch its value
      * The model fetches the ordering ID first, not the value directly, mirroring the position-based mechanism from Paper 1
* Extended setting: explicit visibility information ("Bob can observe Carla's action, but Carla cannot observe Bob's action")
   * Now the correct answer to "What does Bob believe the cup contains?" is "coffee," not "unknown"
   * Steps 1 and 2 remain the same
   * Step 3 (new): model creates a visibility ID on the visibility sentence itself
   * Step 4: visibility ID augments the queried character token, adding the second character's ID to its representation
   * Step 5: the augmented ID is passed to the final token, which can now correctly identify and retrieve the coffee token
* Framework: causal abstraction
   * Construct a high-level causal model with explicit variables describing how input transforms to output
   * Design interventions for each variable; apply them to the low-level model
   * If the model's behavior matches the causal model's predictions, the variables are confirmed; if not, refine and repeat
* Audience question (from chat): when the model gets the belief question wrong, which step breaks?
   * Nikhil: not yet studied in detail, but the approach is clear
   * Find a failing sample and a matching correct sample; patch each mechanism variable from the correct run into the incorrect run; the earliest variable whose patching fixes the output is where the error originates
* Key contributions:
   * Extends Paper 1's finding: position-based representations are not just generated but actively processed and manipulated for far more complex reasoning
   * Demonstrates that causal abstraction scales to multi-character, multi-step belief-tracking tasks

## Paper 3 and 4: Reversible Sentences and Vision-Language Models

### Paper 3: Binding in Reversible Sentences (Work in Progress, Not Yet Submitted)

* Motivation: Papers 1 and 2 used irreversible sentences (e.g., "Box G contains an apple" cannot be swapped without breaking meaning)
   * Reversible sentences: nouns of the same type can be swapped and the sentence still makes sense (e.g., "Alice introduced Bob to Charlie" vs. "Bob introduced Alice to Charlie")
   * How does the model resolve binding when nouns are semantically interchangeable?
* Two competing hypotheses presented to the audience:
   * Hypothesis 1: granular positional indices
      * Model assigns noun-level IDs (noun 1, noun 2, noun 3) within each sentence, combined with a sentence-level ID
      * Uses these to locate the correct noun across the full prompt
   * Hypothesis 2: thematic roles (a linguistic concept)
      * Each noun is tagged with its role: agent (the one acting), recipient, topic, etc.
      * When processing a question, the model identifies which thematic role is being asked about and which sentence it belongs to, then retrieves the matching noun
      * Example: "Jennifer" is the agent of sentence 2; the model queries for "agent of sentence 2" and retrieves "Jennifer"
* Audience vote: most voted for a combination of both; Nikhil confirmed this matches current results
   * Neither hypothesis holds in its pure form; the answer appears to be a hybrid
   * This is an ongoing investigation with no final conclusions yet

### Paper 4: Spatial Variable Binding in Vision-Language Models (Under Review, Workshop Spotlight)

* Architecture: standard VLM with a vision encoder, a projector (maps vision space to language space), and a language model backbone receiving both visual and text tokens
* Task: synthetic colored squares; question: "What is the color of the square to the left of the green square?" (answer: red)
   * Synthetic images used for cleaner results; real images also studied but not presented
* Prior work had shown VLMs use ordering IDs for spatial binding; this paper asks where those IDs come from and how they are structured
* Finding 1: ordering IDs are present in visual token embeddings entering the language model
   * Linear probe trained on visual token embeddings (red = 1, green = 2, blue = 3) achieves near-perfect test accuracy
   * Confirms the vision encoder generates ordering information before the language model sees it
* Finding 2 (surprising): ordering information is diffused across background tokens, not localized to object tokens
   * Probe trained only on object tokens; when applied to all tokens, the ordering signal appears in background tokens around the object location
   * Pattern holds across different numbers of squares (4, 9, etc.) and different orientations
* Causal confirmation: two patching experiments to test whether background token representations are causally relevant
   * Experiment 1: patch only the visual token embeddings of the square tokens from counterfactual to clean run
      * Result: output does not reliably change from red to blue; patching object tokens alone is insufficient
   * Experiment 2: patch the visual token embeddings of the entire region (object + background tokens)
      * Result: output changes cleanly from red to blue; background tokens are causally necessary
* Finding 3: both vision encoder and language model backbone contribute ordering information
   * To isolate the language model's contribution, ordering information was destroyed in the vision encoder
      * Method: patch each square's visual tokens from a single-square image (destroying relative order) and patch background tokens from a blank image
      * Behavioral performance drops significantly but remains above chance
   * Interchange intervention on the language model backbone (after destroying vision encoder ordering) still reveals ordering representations in middle layers
   * Conclusion: vision encoder is the dominant, primary source; language model backbone is a secondary enhancer
* Finding 4: the two sources encode different types of positional information
   * Vision encoder: more absolute position (coordinates, e.g., "I am at position 3,5")
   * Language model backbone: more relative/abstract position (e.g., "I am the first object," "I am the second object")
   * Intervention experiment to distinguish absolute vs. relative:
      * Two images with squares shifted left/right, but blue square at identical absolute coordinates
      * Patch green-to-green and blue-to-blue; change the question to "what is the color of the leftmost square?"
      * If relative: output should become blue (blue is now "first" in the counterfactual)
      * If absolute: output should become brown (brown retains the lowest absolute coordinate)
      * Result: approximately 0.475 for brown, 0.407 for blue, suggesting a roughly even split
      * Interpretation: models encode both, because they must answer both relative and absolute spatial questions
* Audience question (Jacob): why patch background tokens from a blank image rather than, e.g., tiling the middle square's representation?
   * Nikhil's assumption: the relevant information is abstract/relative (first vs. third square), not absolute pixel coordinates, so a blank image cannot represent it; patching from blank destroys the relative signal
   * Jacob's suggestion (tiling middle square representation) noted as an interesting alternative experiment not yet run

## Proposed Goalpost and Future Directions

* Nikhil's self-assessment: after four years and four papers, the field (including his own work) is "touching different parts of the elephant"
   * Each paper reveals a piece of the binding mechanism but no unified, complete account yet
* Proposed goalpost for completion: write executable programs (plain Python or Tracr, which compiles to transformer weights) that simulate how a trained transformer performs variable binding
   * Replace the trained model's weights with the programmatic equivalent
   * If the program matches the trained model's performance across diverse binding tasks, the mechanism is considered understood
   * This is Nikhil's personal benchmark, not yet a field standard
* Two lines of work needed to reach that goalpost:
   * Continued empirical exploration: more settings, edge cases, and binding task variants to build a fuller picture of how binding generalizes
   * Understanding representation generation: how are the ordering IDs and thematic representations actually formed in the first place? Current work characterizes their use but not their origin
* Near-term concrete step: translating the Paper 1 entity-tracking circuit into a Python/Tracr program
   * A mentee is currently working on this
   * Related prior work from Jacob's lab decomposed the QK side of attention into a Python program; Nikhil has not yet tested this himself
* Agentic scaling: Nikhil noted that four years produced four papers and believes agentic research pipelines could significantly accelerate this, potentially removing the need for another full PhD cycle to generate additional papers
* Audience question on generality of ordering IDs: are they used for tasks beyond variable binding?
   * Nikhil's view: binding is so fundamental that almost every task requires it at some level; ordering IDs are likely involved broadly, but he is not aware of a task where IDs are used without binding being the underlying requirement
   * Possible exception raised: factual recall, where it is unclear whether ordering IDs are necessary
